# 1. Общее описание

Игроки собираются в Foundry VTT.

Мастер регистрирует участников игры (себя и других) в мире Foundry и начинают играть.
В игре за особые заслуги мастер может выдать игроку одну из зарегистрированных в модуле карточек.
Игрок в ходе игровой сессии принимает решение об использовании карточки, чтобы в игре произошло событие, соответствующее описанию этой карточки.
Мастер реагирует на использование карточки в соответствии с её описанием.
После выполнения условий карточки, игрок теряет использованную карточку.

> Карточки можно заработать в одной игре (мире Foundry), а использовать в этой игре или любой другой.
> Сами карточки привязаны только к игроку, а не его персонажам в игре.

Мастер также может зарабатывать карточки и использовать их в играх с одним ограничением: на которой игре мастер получил карту, на той же игре и может применять.
Для реализации этой механики мастер для разных игр заводит себе разных мастер-игроков, а не привязывает к разным играм один профиль мастера.

Карточки могут относиться к различным категориям (или уровням) карточек, зарегистрированным в системе.
Категории карточек имеют собственное название и описание.
Внутри уровня каждая карточка имеют уникальный номер.
Для обеспечения гибкости в управлении карточками номера карт не обязательно должны идти последовательно, что может произойти, к примеру, после удаления из категории одной или нескольких карт.

> Карточки не являются неотъемлемой частью модуля.
> Их можно создать и распространять отдельно. 

Задача модуля Foundry VTT "kripta cards" - обеспечить автоматизацию этого игрового процесса с удобным графическим интерфейсом внутри игровой среды Foundry VTT.
В качестве хранилища данных и игрового-процесса используется REST Web API "Web API server" (далее по тексту - Сервер модуля).
Актуальная версия Сервера модуля - 1.0.0.
Сервер модуля разворачивается на машине под управлением Windows или Linux, доступ к нему осуществляется в сетевом расположении.
Требуется настройка Сервера модуля перед запуском.

Наличие отдельного Сервера модуля предоставляет возможность без дополнительных действий переносить данные о карточках между играми.
Для упрощения управления карточек мастером игры, данные о карточках расположены в файловой системе Сервера.
Регистрация карточек происходит путём правки текстового файла "Реестр карточек" и загрузки изображений рядом с текстовым файлом.
При запуске Сервер модуля читает данные из файловой системы и передаёт данные о карточках запрашиваемому браузеру.

В качестве человекопонятного интерфейса используется интерфейс Foundry VTT с доработками модуля `Foundry module\dmicher-kripta-cards` (далее по тексту - Интерфейс модуля).
Интерфейс модуля связывается активируется как модуль в Foundry VTT и после настройки связывается с Сервером модуля для выполнения игровых процессов с карточками.

При переключении между играми контекст миров Foundry VTT  меняется, но контекст Сервера модуля остаётся.
Модуль не зависит от систем и миров: вы можете использовать один экземпляр Сервера, чтобы обслуживать сразу несколько несвязанных миров и игровых систем, для удобства разделяя карточки по категориям.

# 2. Части модуля

Модуль разделен на две большие части: Сервер и Интерфейс.
Обе части не работают друг без друга.
Сервер обеспечивает хранение данных о карточках и перенос их между мирами.
Интерфейс позволяет игрокам и мастеру игры пользоваться карточками в мирах, в которых этот модуль подключен.

- Сервер: `Web API server\KriptaCardsWebServer` (исходный код)
- Интерфейс: `Foundry module\dmicher-kripta-cards` (исполняемый код)

> Для работы сервера требуется его компиляция.
> Воспользуйтесь `https://github.com/dkubrow-dev/kripta-cards/releases` для получения актуальной сборки исполняемого кода для установки.

# 3. Стартовая настройка модуля

Перед запуском требуется настройка Сервера и Интерфейса модуля.
Для использования одного Сервера модуля для разных игр достаточно провести одну настройку Сервера, а дальше только настраивать Интерфейс модуля в разных играх.
Сначала стоит настроить Сервер и убедиться, что он работает, затем переходить к настройке Интерфейса.

## 3.1 Настройка Сервера модуля

Распакуйте Сервера модуля в удобную для вас папку, откуда Сервер будет работать (далее по тексту - Рабочая папка Сервера, ПРС).

Для настройки сервера нас будут интересовать:
- `{РПС}\appsettings.json` - основной файл настроек;
- `{РПС}\Content\CardsReg.json` - файл "Реестр карточек";
- `{РПС}\Content\Cards\` - папка изображений для карточек, разложенных по подпапкам-категориям.

### 3.1.1 Наполнение Реестра карточек содержимым

Чтобы в модуле появились карточки (их описания и изображения), нужно положить изображения карточек в папку `{РПС}\Content\Cards\` и заполнить реестр карточек `{РПС}\Content\CardsReg.json`.

Если вы уже имеете комплект карточек, предназначенный для модуля, то его достаточно распаковать в папку `{РПС}\Content` с заменой всех файлов.

Вы можете сами создать комплект карточек и вложить их в `{РПС}\Content` по следующим инструкциям.
Откройте файл "Реест карточек" в текстовом редакторе (notepad в Windows, nano в Linux и другие).
Файл представляет собой объект в JSON формате, в котором вы найдёте два массива данных:
- `Levels` - перечисление категорий (уровней) карточек;
- `Cards` - перечисление самих карточек.

Если файла не оказалось, или он оказался пустым, заполните его пустым содержимым:

``` JSON
{
  "Levels": [
  // блоки с категориями через запятую
  ],
  "Cards": [
  // блоки с карточками через запятую
  ]
}
```

Чтобы добавить новую категорию карточек добавьте в массив `Levels` следующий блок:

``` JSON
{
  "Id": 0,
  "Name": "Имя категории",
  "Description": "Более подробное описание категории"
}
```
, где:
- `Id` - уникальное целое неотрицательное (0 и больше) число - идентификатор категории карточек;
- `Name` - имя категории карточек для отображения заголовка в Интерфейсе модуля;
- `Description` - более длинное описание категории карточек для отображения в Интерфейсе модуля.

Заполните `Id` категории первым свободным неотрицательным числом, введите произвольные `Name` и `Description` для категории.
Если нужно добавить несколько категорий, разделяйте блоки запятой `,`.
Не стоит использовать html-разметку и специальные символы.
Сохраните файл.

> Перед внесением изменений в Реестр карточек стоит делать резервную копию реестра файла, чтобы иметь возможность вернуться к предыдущей версии, если внесённые изменения окажутся невалидными.

Перейдите в путь `{РПС}\Content\Cards\` и создайте там папку с названием, соответствующим `Id` категории.
Эта папка будет использоваться для хранения изображений карточек только что заведённого уровня.
Разместите в папке изображения карточек, задав им имя по формату `N.ext`, где `N` - уникальный номер карточки в категории, а `ext` - расширение, соответствующее формату файла.

Для стабильного отображения изображений используйте форматы файлов `png`, `jpg` или `webp`.
Конвертируйте файлы при необходимости.
Рекомендуется использовать единые или близкие размеры изображений с соотношением сторон 1 к 1 (квадратные).
Не рекомендуется использовать изображения больше чем 800x800 пикселей.

Вернитесь к файлу Реестра карточек и зарегистрируйте карточки в объекте `Cards`. Для регистрации карточки добавьте в массив следующий блок:

``` JSON
{
  "Level": 1,
  "Number": 40,
  "Name": "Название карты",
  "Description": "<p>Подробное описание карты с html...</p>"
}
```
, где:
- `Level` - одно из чисел, зарегистрированных в массиве категорий - ссылка на уникальный номер категории: то, к какому уровню относится карточка; укажите строго существующий уровень, иначе Сервер не станет работать;
- `Number` - целое неотрицательное (0 или больше) число - уникальный номер карточки в пределах уровня;
- `Name` - название-заголовок карточки для отображение в Интерфейсе модуля;
- `Description` - описание карточки для отображения в Интерфейсе модуля; в этом поле допустима несложная html разметка.

Заполните `Level` ссылкой на только что заведённую категорию, `Number` номером изображения, которое вы добавили ранее в папку с изображениями категории, `Name` и `Description` описаниями карты.
Если нужно добавить несколько карточек, разделяйте блоки запятой `,`.
Сохраните файл.

Если вам надо будет удалить карточки, удалите блок карточки из файла репозитория (включая запятую, отделяющую блок от других).
Стоит также удалить изображение карточки, но это не обязательно.
Если требуется удалить целую категорию (уровень) карточек, удалите сначала все вложенные в категорию карточки, затем - уже саму категорию.

Вы можете перенести карточку в другую категорию, поменяв ей заявленный уровень и уникальный номер в категории.
Тогда не забудьте перенести и изображение карточки в другую папку.


Для заведения одной и той же карточки в разных категориях заведите два разных блока для карточки в Реестре и расположите два изображения карточки в разных подпапках-категориях.

Пример заполненного реестра карточек:

``` JSON
{
  "Levels": [
    {
      "Id": 0,
      "Name": "База",
      "Description": "Самые нужные и полезные карты, пусть и слабые"
    },
    {
      "Id": 2,
      "Name": "Рарно",
      "Description": "Редкие карточки, попробуй добудь"
    },
  ...
    {
      "Id": 197,
      "Name": "Последняя категория!",
      "Description": "197 категория! Пффф... это было долго"
    }
  ],
  
  "Cards": [
    {
      "Level": 0,
      "Number": 1,
      "Name": "Воля",
      "Description": "<p>Потратье карту и совершите с преимуществом проверку Харизмы.</p>"
    },
    {
      "Level": 0,
      "Number": 2,
      "Name": "Сила",
      "Description": "<p>Потратьте карту и добавьте ваш БМ к следующей проверке Силы.</p>"
    },
  ...
	{
      "Level": 197,
      "Number": 14,
      "Name": "Корзина",
      "Description": "<p>Потратье карту: на голову выбранного персонажа...</p>"
    }
  ]
}
```

Структура папок для такого реестра будет примерно следующей:

```

  │ ├── 1.png

  ├─┬─ 1
  │ ├── 1.png
  │ ├── 2.png
  │ ...
  │ └── 79.png
  ...
  └─┬─ 197
    ├── 1.png
    ├── 2.png
    ...
    └── 14.png
```


### 3.1.2 Настройка Web API

Откройте файл `{РПС}\appsettings.json` текстовым редактором (notepad в Windows, nano в Linux и другие).
Вы обнаружите примерно следующее содержание:

``` JSON
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "UserAuth": {
    "Users": [
      {
        "Id": "Логин_для_Writer",
        "Key": "Ключ_для_Writer",
        "Role": "Writer"
      },
      {
        "Id": "Логин_для_Reader",
        "Key": "Ключ_для_Reader",
        "Role": "Reader"
      }
    ]
  },
  "Cors": {
    "AllowedOrigins": [
      "https://origin1.foundry.org",
      "https://localhost:31311",
      "https://192.168.0.1:12343"
    ]
  },
  "Kestrel": {
    "Endpoints": {
      "Http": {
        "Url": "http://0.0.0.0:61532"
      }
    }
  },
  "AllowedHosts": "*"
}

```

Содержимое этого файла надо поменять, чтобы Сервер модуля мог принимать запросы из браузеров игроков, а современные браузеры не блокировали запросы.

**Блок Logging** - настройка уровней логгирования.
В большинстве случаев достаточно оставить без изменений.
Уровни логгирования отвечают за подробность, с которой сервер ведёт записи действий с ним в папке `{РПС}\logs` и вложенных подпапках.
Не изменяйте уровень логгирования, если не уверены в том, что делаете.

**Блок UserAuth** - настройка пользователей Сервера, под которыми Интерфейс модуля будет аутентифицироваться во время выполнения запросов.
В массиве `Users` указаны 2 блока, которые нужно заполнить своими данными.
Эти данные нужны будут дальше при настройке Интерфейса модуля.
Пользователь, для которого `"Role": "Writer"` - это технический пользователь сервера, который выполняет операции записи и управления на Сервере модуля.
Пользователь, для которого `"Role": "Reader"` - это технический пользователь, под которым будут отправляться запросы на чтение данных с Сервера без их изменения.

> Стоит отметить: пользователи Writer и Reader не относятся к Игрокам Сервера и Участником Foundry - это технические записи, которые позволяют немного структурировать работу Сервера модуля, не давая доступ кому-то стороннему выполнять действия на Сервере.
> Держите логины и ключи пользователей в секрете.

Для обоих пользователей `Writer` и `Reader` заполните поля `Id` и `Key`.
Поле `Role` не изменяйте.

**Блок Cors** - настраивает Сервер таким образом, чтобы запросы из Foundry-клиентов игроков не блокировались современными браузерами на разных этапах отправки и получения.
Здесь вам надо указать все адреса, по которым вы и ваши игроки будут заходить на Foundry VTT для игры.
Укажите адреса в кавычках через запятую.
Приводить можно как через IP+Port, так и через доменное имя (если оно есть).

**Блок Kestrel** - настраивает IP и порт, на котором запустится сам Сервер модуля.
Стоит оставить настройку без изменений, если вы не уверены, что именно она делает.

**Настройка AllowedHosts** - дополнительная настройка проверки имён хоста в HTTP-запросах к Серверу модуля.
Эта настройка не заменяет блок Cors и обычно может быть оставлена без изменений (`"*"`), если вы не уверены, что именно хотите ограничить.

### 3.1.3 Запуск Сервера

#### 3.1.3.1 Тестовый пуск Сервера

Для быстрого запуска сервера после настройки в Проводнике Windows кликните дважды по файлу `{РПС}\KriptaCardsWebServer.exe`.
Для запуска из командной строки Windows:

``` Bash
cd {РПС}
./KriptaCardsWebServer.exe
```

, где `{РПС}` - рабочая папка Сервера (при наличии пробелов в пути не забудьте поставить кавычки).

Для быстрого запуска сервера в Linux выполните:

``` Bash
cd {РПС}
dotnet ./KriptaCardsWebServer.dll
```

Сервер запустится и выведет к консоль (термирал) примерно следующие сообщения:

```
Now listening on: http://0.0.0.0:61532
Application started. Press Ctrl+C to shut down.
Hosting environment: Production
Content root path: {РПС}
```

После этого откройте браузер и перейдите по адресу `http://localhost:61532/api/health/check` - для проверки, что сервис вообще работает.

В браузере вы должны будете увидеть вывод:

```
Status: running
Assembly: KriptaCardsWebServer
Version: 1.0.0
Author: dmicher abathur kubrow
```

После этого проверьте доступность этого же метода по вашему внешнему HTTP(S) URL, если он у вас настроен.

Сервер запущен и готов к работе: можно переходить к настройке Интерфейса модуля.

#### 3.1.3.2 Установка и удаление Сервера как службы Windows

Для установки Сервера в Windows настройте и проверьте запуск сервера вручную по пункту 3.1.3.1, затем, запустите `{РПС}\KriptaCardsWinServiceManager.exe` от имени администратора и выберите пункт установки службы в операционную систему.
Откройте меню `Службы` администрирования Windows и убедитесь, что служба `Kripta Cards Web API Server` зарегистрирована и запущена.
Теперь вы можете управлять службой из этого меню.

Для удаления службы запустите `{РПС}\KriptaCardsWinServiceManager.exe` от имени администратора и выберите пункт удаления службы.

#### 3.1.3.3 Установка и удаление Сервера как службы Linux

Для установки Сервера в Linux убедитесь, что служба `systemd` установлена в ядре операционной ситемы, настройте и проверьте запуск сервера вручную по пункту 3.1.3.1, затем, для скрипта `KriptaCardsLinuxServiceInstaller.sh` установите флаг запуска на исполнение и запустите скрипт от имени sudo-пользователя.

``` Bash
cd {РПС}
chmod +x KriptaCardsLinuxServiceInstaller.sh
sudo ./KriptaCardsLinuxServiceInstaller.sh
```

Для остановки и удаления Сервера выполните то же самое для скрипта `KriptaCardsLinuxServiceUninstaller.sh`.

## 3.2 Настройка Интерфейса модуля

### 3.2.1 Подключение модуля к Foundry VTT

#### 3.2.1.1 Подключение модуля через архив

Интерфейс полностью содержится в папке `FoundryModule\dmicher-kripta-cards`.
Положите папку `dmicher-kripta-cards` в директорию `{ППД}/Data/modules`, где `ППД` - папка пользовательских данных Foundry VTT.

Папка пользовательских данных в Foundry VTT настраивается в интерфейсе Foundry.
После запуска приложения Foundry на начальном экране откройте меню `Настройки`, блок `Настройки Foundry VTT`, поле `Пользовательские данные`.
По умолчанию в Windows путь будет примерно следующий: `C:/Users/<user>/AppData/Local/FoundryVTT`, где `<user>` - имя вашего пользователя Windows.

Перезагрузите Foundry VTT и войдите на стартовую страницу.
На вкладке `Модули` должен появиться модуль с именем `dmicher's Kripta Cards`.

#### 3.2.1.2 Подключение подуля через манифест

Запустите Foundry VTT и войдите в основное меню.
Затем, выберите меню модулей и нажмите на кнопку `Установить модуль`.
В нижней части появившегося окна в поле `Ссылка на манифест` укажите ссылку `https://github.com/dkubrow-dev/kripta-cards/releases/latest/download/module.json` и нажмите кнопку `Установить`


### 3.2.2 Настройка модуля в игре

Перейдите в игровой мир, в котором намерены использовать модуль.
Зайдите в мир под ролью мастера игры, дождитесь полной загрузки интерфейса.
Откройте `Настройки игры` Foundry VTT, находясь в игровом мире.
В открывшемся окне `Настройки` выберите раздел `Карточки Крипты` - слева отобразится перечень настроек модуля для подключения к Серверу модуля:

1. В поле `Путь к Серверу` укажите сетевой путь, по которому сервер доступен для Foundry-клиентов игроков.

Нажмите кнопку `Проверить сервер`.
Модуль обратится к запущенному Серверу по адресу, чтобы проверить его доступность.
В ответ вы получите сообщение от модуля о результате проверки.

2. Заполните в блоках `Писатель (Writer)` и `Читатель (Reader)` пары полей `Идентификатор (Id)` и `Ключ (Key)`.

Данные об идентификаторе и ключе вы заводили в пункте 3.1.2.
Нажмите кнопку `Проверить тех.пользователей`.
Модуль дважды обратится к Серверу с переданными данными, чтобы подтвердить, что введённые данные позволяют аутентифицироваться на сервере под соответствующими ролями.

> Учётные данные сервера `Писатель (Writer)` и `Читатель (Reader)` хранятся в данных игрового мира Foundry в `world setting` в словаре `tech-auth-users` в блоках `writer` и `reader`.
> В интерфейсе участник Foundry, не являющийся мастером, не увидит этих полей для заполнения.
> Однако значения этих полей используются браузерами игроков для подключения к Серверу модуля.
> Разделение пользователей `writer` и `reader` в контексте модуля - это организационно-практическое, а не криптографическое ограничение доступа.

3. Если хотите, нажмите кнопку `Сказать спасибо автору`.

Нажатие на кнопку откроет новое окно браузера с адресом страницы благодарностей автору модуля.

4. Нажмите кнопку `Сохранить изменения`, чтобы настройки вступили в силу. Закройте окно без нажатия кнопки сохранения, чтобы сбросить изменения.

### 3.2.3 Привязка Игроков Сервера к Участникам Foundry

Откройте `Управление участниками` Foundry VTT, находясь в игровом мире.
Настройте участников игрового мира по своему усмотрению.
Сохраните настройки.

Откройте окно `Управление игроками` из меню модуля `Карточки крипты` в меню кнопок слева-сверху.
Для каждого игрока из списка через кнопку `Привязка` привяжите Игрока Сервера.

> Для создания и изменения Игроков Сервера нажмите кнопку `Реестр игроков`: откроется соответствующее окно, через которое вы управлять данными на Сервере.
> После создания Игрока Сервера вернитесь на страницу `Управление игроками`, чтобы продолжить работу по привязке игроков к участникам Foundry.

Настройте привязку для всех игроков, включая себя, чтобы каждый Участник Foundry был сопоставлен Игроку Сервера по правилу "один к одному".

> Для одного и того же человека в разных играх вы можете установить как новые объекты `Игрок` так и привязать старый.
> При привязке нового игрока для каждой игры карточки будут строго внутри этой игры, для привязке одного игрока к нескольким играм, карточки будут "свободно гуляющими".
> Пользуйтесь комментариями, чтобы не запутаться в игроках.

После завершения привязки Участников Foundry к Игрокам Сервера настройка модуля завершена.

> При удалении мира из Foundry информация о привязках игроков к участнику этого мира пропадёт вместе с ним.
> При необходимости эту информацию придётся восстанавливать вручную.
> Однако, удаление мира никак не скажется на выданных игрокам карточках.
> Информация об этом хранится на Сервере модуля: игроки по прежнему смогут использовать ранее полученные в удалённом мире карточки в других играх и мирах.

# 4 Использование модуля

## 4.1 Структура меню "Карточки крипты"

Модуль формирует свою категорию в меню кнопок Foundry слева сверху (в том же меню, что и `Инструменты токенов` и другие).
Кнопка первого уровня `Карточки крипты` - главная кнопка меню.
Остальные кнопки входят во второй уровень меню и скрываются при переключении на другую категорию кнопок.
При нажатии отображаются внутренние кнопки.

Кнопки второго уровня:
- `Каталог карточек` - открывает соответствующее окно для просмотра всех возможных карточек; кнопка доступна всем игрокам;
- `Получить карточку` - используя привязку "Участник Foundry - Игрок Сервера" открывает окно `Получить карточку`, минуя окно `Карточки игрока`; если привязки нет, выдаёт сообщение о том, что игрок не привязан; эта кнопка доступна всем игрокам;
- `Мои карточки` - открывает окно `Карточки игрока`, используя привязку "Участник Foundry - Игрок Сервера"; если привязки нет, выдаёт сообщение "Ваш Участник Foundry не привязан к Игроку Сервера в модуле Карточки крипты. Обратитесь к мастеру игры"; кнопка доступна всем игрокам;
- `Управление игроками` - открывает окно `Управление игроками` для управления привязками "Участник Foundry - Игрок Сервера"; видна и доступна только мастеру игры.

## 4.2 Окна и игровые процессы

## 4.2.1 Окно "Каталог карточек"

Окно `Каталог карточек` - информационный справочник всех зарегистрированных карточек.
Окно открывается из меню модуля по кнопке `Каталог карточек`.

Слева отображается меню всех зарегистрированных категорий, справа - карточки выбранной категории. Выбранная категория подсвечивается в меню цветом и рамкой.

В шапке страницы над карточками можно увидеть:

- название и описание выбранной категории;
- поле для поиска карточки внутри категории;
- кнопки `Таблица` и `Плитки` для изменения способа отображения карточек.

Для каждой карточки указывается:
- изображение карточки;
- название и описание карточки;
- кнопка `Вывести`, чтобы показать карточку в чате;
- кнопка `Информация`, чтобы открыть карточку в отдельном окне;
- (только мастеру) кнопка `Выдать`, чтобы выдать эту карточку какому-то игроку.

Внизу каталога отображается кнопка `Обновить`. Она позволяет перезагрузить карточки с сервера, если они там были изменены.

## 4.2.2 Окно "Получить карточку"

Окно `Получить карточку` позволяет игроку запросить случайную или конкретную карточку из всего набора зарегистрированных карточек.
Окно можно вызвать из меню модуля по кнопке `Получить карточку` и из окна `Карточки игрока` по кнопке `Получить`.

Когда окно появляется, игрок может выбрать категорию, из которой будет выбрана карточка, затем, режим получения:

- `Случайная` - будет выбрана случайная карточка из выбранной категории;
- `На выбор` - можно выбрать из списка карточек выбранной категории одну конкретную.

После нажатия на кнопку `Запросить` в окне в чат будет выведен запрос для мастера игры на выдачу карты. В режиме `Случайная` запрос будет начинаться со слов "Случайная карта", а в режиме `На выбор` - "Выбрана карта".

Мастер игры будет видеть кнопки управления запросом:

- `Подтвердить` - запрос будет подтверждён, карта выдана;
- `Отменить` - запрос будет отменён, карта не будет выдана.

При отмене или подтверждении запроса исходное сообщение будет удалено. Если карта подтверждена, то в чат будет выведено сообщение о том, что игрок получил карту.

> Обратите внимание. Вся выводимая информация в чат зависит от выбранного режима броска: если выбран публичный бросок, он будет виден всем, если приватные - то тем, кому бросок предназначен.

В окне `Карточки игрока` получение новой карточки будет видно только после перезагрузки окна и/или после нажатия кнопки `Обновить`.

## 4.2.3 Окно "Карточки игрока"

Окно `Мои карточки` позволяет игроку следить за карточками, которые он получил, и использовать их в игре.
Окно `Карточки игрока` открывается из меню модуля по кнопке `Мои карточки` для каждого игрока - своё.
Мастер может также открыть окно `Карточки игрока` для любого иного игрока из окна `Управление игроками`.

Слева в окне отображается меню всех зарегистрированных категорий, справа - карточки выбранной категории, которыми игрок обладает. Выбранная категория подсвечивается в меню цветом и рамкой.

В шапке страницы над карточками можно увидеть:

- название и описание выбранной категории;
- поле для поиска карточки внутри категории;
- кнопки `Таблица` и `Плитки` для изменения способа отображения карточек.

В режиме `Плитки` (режим по умолчанию) для карточки указывается:
- изображение;
- название;
- количество;
- описание (отображается при наведении мыши);
- кнопка `Использовать` для использования карты или вывода информации о ней.

> При нажатии на блок в режиме `Плитки` подробна информация о карточке открывается в отдельном окне.

В режиме `Таблица` для карточки указывается:
- изображение;
- название и рядом количество карточек этого типа;
- описание;
- кнопка `Использовать` для использования карты или вывода информации о ней;
- кнопка `Информация` для открытия подробной информации в отдельном окне;
- (для мастера) кнопка `Забрать` для отъёма карточки у игрока без вывода информации в чат.

## 4.2.4 Окно "Управление игроками"

Окно `Управление игроками` доступно только мастеру игры.
Оно нужно для настройки модуля, а также для просмотра карточек, выданных другим игрокам.
Окно открывается из меню модуля по нажатию кнопки `Управление игроками` (видит только мастер).

В окне отображаются все зарегистрированные в текущем мире Foundry VTT участники.
Регистрация участников - базовый функционал Foundry внутри мира: `Настройки игры` - `Управление участниками`.

Для каждого участника Foundry выделен отдельный блок.
Внутри каждого блока базовая информация:
- имя и роль участника в мире;
- данные о привязанном участнике Сервера модуля;
- кнопка `Привязать` для первичной привязки или изменения привязки игрока Сервера к участнику мира;
- кнопка `Отвязать`, чтобы убрать привязку игрока Сервера от участника мира;
- кнопка `Карточки игрока`, чтобы открыть одноимённое окно и посмотреть карточки, выданные этому игроку;
- кнопка `Выдать карточку`, чтобы выдать игроку карточку, минуя запрос на её получения от самого игрока;
- также отображается количество типов карточек, которые имеет игрок (учитываются только уникальные карточки, без повторов).

Для создания, изменения и удаления игроков Сервера модуля, можно открыть окно `Реестр игроков` по одноимённой кнопке внизу окна `Управление игроками`.
